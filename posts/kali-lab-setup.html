My Kali Linux Lab
Setup

An isolated VirtualBox environment on Kali Linux — Windows 7/10/11, a Kali guest, and Metasploitable-2 — built to study how Windows Defender and Google Play Protect actually respond to commercial RATs, without ever touching a device that isn't mine.

#kalilinux #virtualbox #pentestlab #windowsdefender #malwareanalysis #redteam
Host
Kali Linux (Rolling)
Guest VMs
Win 7/10/11, Kali, Metasploitable-2
Network
NAT — 10.0.0.x
Isolation
Snapshots
// OVERVIEW

I run Kali Linux as my host OS directly — I tried Arch with Hyprland for a while, but for day-to-day offensive security work Kali's tooling and driver support just fit better, and it keeps the host and guest distros consistent. On top of that host I run a VirtualBox lab that I use for two different kinds of work: general pentest practice, and — the part I'm most focused on right now — studying how Windows Defender and Google Play Protect actually detect and respond to commercial RATs.

// Scope note: Every test in this lab runs against my own VMs and my own devices only. No sample is ever run against, or distributed to, a system I don't own. The goal is building detection and defense knowledge, not building tools to use on anyone else.
// STEP 1 — HOST + VIRTUALBOX
01Kali as the host, VirtualBox on top

The host is Kali Linux (rolling release) on an MSI Modern 14 (i5-1235U, 8GB RAM). VirtualBox runs directly on the host and hosts every guest VM below. Keeping Kali as the host — rather than running it as a guest inside something else — means the tooling I use to observe and interact with the guests (Wireshark, process monitors, network capture) is right there on the same machine.

// STEP 2 — GUEST VMs
02What's actually running

Four guest VMs, each with a specific job:

VMPurpose
Windows 7 / 10 / 11Defender-focused RAT testing — different Defender/SmartScreen behavior per version
Metasploitable-2Deliberately vulnerable Linux target for exploitation practice
Kali (guest)Used for heavier engagements where I want the attacker box further isolated from the host itself
BASH VBoxManage list vms # lists every registered guest — quick sanity check before a session
// STEP 3 — NETWORK ISOLATION
03NAT-only, snapshot-first

Every guest is on a NAT network — VirtualBox puts them on a private 10.0.0.x subnet. They get outbound internet, but nothing on my real LAN (router, phone, other machines) can reach in, and the guests can't reach out to the LAN either without explicit port forwarding. No bridged adapters anywhere in this lab.

Before running anything live, I take a snapshot. After the test, I revert. Every sample runs against the exact same clean state — no leftover artifacts from a previous test skewing what I'm observing.

// Why this matters: isolation isn't just "best practice" boilerplate — it's what makes it safe to run a live RAT sample at all. Without NAT isolation + snapshots, I wouldn't run this stuff.
// STEP 4 — RAT / AV DETECTION RESEARCH
04What I'm actually testing

Inside the isolated Windows VMs, I've been running commercial/publicly-documented RATs and observing — not modifying or building — how Windows Defender's real-time protection reacts: does it flag on-disk, on-execution, or not at all; does SmartScreen intervene; what gets logged. For the Android side, I sideload APKs into an isolated environment to see how Google Play Protect classifies the same category of tool.

I'm keeping this section observational on purpose — the point of documenting it publicly is to show the detection-research methodology, not to publish an evasion guide.

// WHAT I'VE LEARNED SO FAR

Detection isn't uniform — the same category of tool gets treated very differently depending on Windows version, whether Defender's cloud-delivered protection is reachable, and how the sample is delivered (disk vs. memory). That gap between signature-based and heuristic/behavioral detection is where most of the interesting differences show up.

The isolation discipline — NAT-only networking, snapshot-before/revert-after — is what actually makes this kind of research responsible to do at all. It's also, honestly, the part that translates most directly to real red team lab hygiene.
